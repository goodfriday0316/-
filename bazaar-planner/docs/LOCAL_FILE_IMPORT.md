# 개인 파일 기반 덱 플래너

이 기능은 사용자가 보유한 원본 JSON을 직접 선택하여 **브라우저 안에서 변환**하는 방식입니다. 앱 배포본에는 실제 원본 데이터·이미지가 들어 있지 않습니다. 출처 사이트를 호출하거나 접근 제한을 우회하지 않습니다.

## 사용 방법

1. `원본 JSON 불러오기`에서 사용이 허용된 UTF-8 `cards_generated.json` 형식의 파일을 선택합니다. 최대 25MB입니다.
2. 변환 결과의 추가·제외·격리·미해석·활성 불확실 수를 확인합니다. 적용 전에는 기존 개인 도감을 바꾸지 않습니다.
3. `이 파일을 개인 도감으로 사용`을 누르면 도감에 표시됩니다. 기존 검색·필터·드래그·10칸 보드·복제·비교·덱 JSON 저장을 그대로 사용합니다.
4. 변환 도감은 IndexedDB에 저장되어 같은 브라우저·사이트에서 새로고침해도 유지됩니다. 저장소를 사용할 수 없으면 현재 탭에서만 사용한다고 표시합니다.
5. `개인 도감 관리`에서 전체 변환 보고서를 파일로 저장하거나 개인 도감을 지울 수 있습니다. 도감을 지워도 기존 덱의 아이템 사본은 유지됩니다.

원본 파일 전체 바이트는 저장하지 않으며 변환된 아이템·진단 보고서·파일 이름·해시만 브라우저에 보관합니다. 브라우저 데이터 삭제·기기 변경·주소 변경 시 도감은 옮겨지지 않습니다. 원본 파일은 PC에서 따로 보관하고, 덱은 기존 JSON 내보내기로 백업하세요. 덱 내보내기에는 배치된 아이템의 이름·효과·수치 사본이 포함되므로, 그 파일을 다른 사람에게 재배포할 권한은 별도로 확인해야 합니다.

## 변환 범위

- 이름을 키로 하는 객체의 `Item` 레코드를 처리합니다. 스킬과 그 밖의 타입은 제외합니다.
- `source_id`를 우선 고유 ID로 사용하고, 없으면 유효한 `id`를 사용합니다. 둘이 다르면 격리합니다. 이름으로 ID를 만들지 않습니다. 출력 ID는 `local-raw:<원본ID>`입니다.
- `hero`/`heroes`를 검증하고 복수 영웅을 보존합니다. `Common`은 중립에 대응합니다. `Hero8` 등 확인되지 않은 코드는 추측하지 않고 격리합니다.
- 소형·중형·대형 문자열을 1·2·3칸으로 변환합니다. 알 수 없는 크기는 격리합니다.
- 브론즈→실버→골드→다이아몬드 순으로 존재하는 등급만 처리합니다. 이전 속성을 이어받고 해당 등급의 명시적 값으로 덮어씁니다. **0은 누락이 아닙니다.** 하위 등급을 새로 만들지 않습니다.
- 선언된 등급의 원본 정보가 없으면 추측 상속하지 않고 격리합니다. null/복합 속성은 의미 미확인으로 경고하고 해당 값을 상속하지 않습니다.
- 능력·지속 효과의 인덱스와 ID 참조를 조회하고 참조 목록을 보존합니다. 생략된 목록을 이전 등급에서 유지할 때는 전체 원본 규칙 미확인 경고를 붙입니다. 명시적 빈 배열은 목록을 비웁니다.
- 디버그·템플릿 표시 및 명시적 비활성 표시는 제외합니다. 일반 이름에 `Test`가 있다는 이유만으로 제외하지 않습니다. 활성 근거가 없는 항목은 **활성 불확실**입니다. 파일이 활성이라고 표시해도 게임 내 활성 검증과 구분합니다.
- 한국어 이름을 생성하거나 비공식 명칭을 공식 번역으로 표시하지 않습니다. 원문의 이름을 유지하고 미번역으로 표시합니다.
- 파일명·커밋 시각으로 패치를 추정하지 않습니다. 현재 화면에서 가져오는 원본은 패치 미확인으로 기록합니다.

## 효과 해석의 한계

`{attribute.X}`처럼 명시적 속성 경로는 해당 등급의 값을 사용합니다. `{ability.인덱스/ID}`와 `{aura.인덱스/ID}`는 참조가 선택된 능력이며, 그 정의에 명시적 `TooltipValue` 또는 `DisplayValue`가 있을 때만 스칼라나 명시적 속성·나눗수 참조를 해석합니다. 이런 표시 필드가 실제 원본 전체에 있다는 보장은 없습니다.

**알려지지 않은 게임 Action 트리나 능력 번호를 피해·회복 등으로 임의 매핑하지 않습니다.** 해석되지 않은 토큰은 `〔미해석: {ability.0}〕`처럼 원문과 함께 보이며 보고서에도 남습니다. 임의의 시간 단위 변환이나 수치 생성은 하지 않습니다. 따라서 원본을 불러와 배치할 수 있어도 모든 효과 설명이 완성되는 것은 아닙니다.

전설 등급은 현재 UI 미지원으로 보고합니다. 다른 지원 등급이 있으면 해당 등급만 표시하고, 지원 등급이 하나도 없는 항목은 격리합니다. 원본 참조의 복잡한 상속·삭제·조건부 액션은 추가 정의 검증이 필요합니다.

## 개인 이미지 ZIP을 위한 준비

현재 ZIP 파서와 업로드 UI는 없습니다. 아래 연결 구조만 준비했습니다.

- 별도 IndexedDB 이미지 Blob 저장소와 읽기·삭제 API.
- 파일 이름의 정확한 원본 ID 또는 명시적 매핑표로 아이템을 찾는 함수. 이름으로 추측하지 않으며 중복 후보는 모호함으로 반환합니다.
- PNG/JPEG/WebP의 경로·크기·파일 시그니처 검사. 원격 URL·경로 탈출·SVG는 받지 않습니다.

향후 ZIP 리더에는 압축 해제 용량·개수 제한, 이미지 크기 검사, 매핑 미리보기 및 Blob URL의 화면 연결·해제를 추가해야 합니다. 원본 JSON에 이미지 URL이 있어도 현재 앱은 가져오거나 자동 표시하지 않습니다.

## 전송 차단과 보안 범위

변환은 Web Worker에서 실행됩니다. Worker로 보내는 `postMessage`는 브라우저 내부 메시지이며 HTTP 업로드가 아닙니다. 네트워크 업로드 코드·외부 분석 스크립트·원격 폰트를 추가하지 않았습니다. 배포 빌드에는 `connect-src 'none'` 정책을 넣어 외부 및 같은 출처의 fetch/XHR/WebSocket 연결을 막습니다. 정적 앱·Worker 파일을 읽는 GET 요청은 필요합니다.

개발 서버의 React 새로고침 통신을 깨뜨리지 않도록 이 정책은 프로덕션 빌드에 적용합니다. 개발 모드에서도 파일 업로드 코드는 없지만 정책 검증은 프로덕션 preview에서 수행합니다. 로컬 파일을 여는 행위가 PC에서 그 파일을 합법적으로 취득·사용했다는 보증은 아닙니다.

## 취득·이용 조건

이 기능은 제3자 사이트의 수집 금지나 접근 제한을 해결하는 수단이 아닙니다. 사용자는 정당하게 보유하고 해당 용도 사용이 허용된 파일만 선택해야 합니다. 개인용·비상업용이라는 이유만으로 원본 JSON, 이미지, 설명문을 공개 웹서버나 덱 파일로 재배포할 권한이 확인되는 것은 아닙니다. 공식 API·팬 콘텐츠 포괄 라이선스·이미지 재배포 허가는 여전히 미확인입니다. 이전 [출처 조사](../research/community-sources.md), [GitHub 조사](../research/github-source.md)와 구분해 읽으세요.

이번 개발은 원본 게임 파일·이미지를 확보하거나 배포하지 않았고 Cloudflare 서비스도 변경하지 않았습니다.
