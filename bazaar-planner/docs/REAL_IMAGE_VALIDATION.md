# 실제 게임 이미지 검증 완료

기존 구현 커밋 aba99d9를 변경하지 않고 사용자 제공 분할 ZIP 6개로 검증했습니다.

## 최종 수치
- 실제 SQLite에서 등록 가능한 메타데이터: 1,117개.
- 실제 WebP 파일: 1,080개.
- template_id UUID 매칭 및 브라우저 디코딩·IndexedDB 저장 성공: 1,080개.
- 매칭 실패, 중복 UUID, ZIP CRC 오류, 손상 이미지: 각각 0개.
- 이미지 없는 아이템: 37개. DB image_path 없음·ignored=1인 항목과 일치.
- ignored는 Chronicle의 표시이며 게임 활성/비활성 여부로 단정하지 않음.
- art_key 대신 검증된 template_id.webp 파일명을 사용.

## 실제 브라우저 검증
- 분할 ZIP별 저장: 187 / 182 / 196 / 189 / 199 / 127장.
- 6개 파일 선택부터 완료 안내까지 측정 시간 합계: 21.622초 (이 클라우드 Chromium 환경에서 측정; PC 성능 보장치 아님).
- 저장한 이미지 Blob 합계: 147,500,472바이트.
- 이미지·도감 포함 IndexedDB 추정 사용량: 149,133,467바이트.
- 메모리 최고 사용량은 측정하지 않음. 실제 분할 ZIP 전체 처리 중 오류 없음.
- 브라우저 JavaScript 오류 0개.
- 실제 이미지 도감·상세·보드 표시 확인.
- 영웅 필터 9개 전환 확인. DB에 Dragons 항목이 없어 해당 필터 결과는 0개.
- 실제 소형/중형/대형 아이템 1/2/3칸 배치 확인.
- 실제 대형 아이템 드래그 이동 후 이미지와 위치 저장·새로고침 복원 확인.
- 실제 아이템을 담은 덱 JSON 다운로드·복원 확인.
- Chromium을 완전히 종료하고 같은 프로필로 재시작해 이미지·도감·덱 복원 확인.
- 기존 합성 데이터 기반 회귀 테스트 13개, 프로덕션 테스트 15개 통과 결과 유지. 이번 검증은 실제 DB·이미지로 추가 수행.

## 사용 순서
1. 앱에서 원본 JSON 불러오기 → Chronicle 변환 JSON 선택 → 개인 도감으로 적용.
2. 개인 도감 관리 → 개인 이미지 ZIP 불러오기 → items-part-001.zip부터 006.zip까지 차례로 선택.
3. 마지막 보고서: 저장 127 / 실패 0 / 이미지 없는 아이템 37. 저장 127은 마지막 파일의 수이며 전체 누적 저장은 1,080장.
4. 덱은 자동 저장되며 JSON으로 백업 가능. 이미지 Blob은 덱 JSON에 포함되지 않음.

검증용 브라우저 저장소가 사용자의 PC로 복사되는 것은 아니므로 사용자의 브라우저에서도 직접 가져오기가 필요합니다.
DB·이미지·브라우저 프로필·실제 이미지 스크린샷은 GitHub와 Cloudflare 배포에 포함하지 않습니다.
현재 게임 활성 여부, 효과·실제 등급, 패치, 외부 상세 URL은 해당 자료에서 확인할 수 없어 추정하지 않습니다.
Cloudflare 직접 배포는 수행하지 않았습니다.
