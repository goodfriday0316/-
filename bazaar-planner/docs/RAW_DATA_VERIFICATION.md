# 원시 아이템 구조 기술 검증

> 이 문서는 b10448d 시점의 서버용 정규화 변환기 진단입니다. 후속 브라우저 전용 어댑터 구현은 [개인 파일 가져오기](LOCAL_FILE_IMPORT.md)에 별도 기록했습니다.

검증일: 2026-10-27. 조사된 `cards_generated.json`의 **필드 구조만** 참고하여 직접 만든 합성 데이터로 검사했습니다. 실제 게임 이름·ID·수치·효과·이미지를 가져오지 않았습니다. UI, 배치·저장 기능 및 변환기 본체를 변경하지 않았고 Cloudflare 배포·원격 push도 하지 않았습니다.

## 결론

현재 변환기는 정규화된 공급자 JSON을 처리합니다. **원시 cards_generated.json 호환은 아직 미완료**입니다. 아래 진단 테스트가 통과했다는 것은 지원 기능과 미지원 동작을 재현했다는 뜻이며, 원시 데이터 변환 정확성 전체가 통과했다는 뜻이 아닙니다.

테스트: `tests/raw-data-contract.test.mjs` — 지원 3건, 미지원 확인 7건, 지원 경계 1건, 안전성 1건, 총 12건.

| 항목 | 확인한 동작 | 판단 |
| --- | --- | --- |
| 정규화된 ID | 이름을 바꾸어도 ID와 공급자 네임스페이스 유지. 같은 ID의 충돌 데이터 거부 | 지원 |
| 정규화된 영웅·크기·등급 | 검증된 영웅 배열, 숫자 1/2/3, 명시적 등급별 값 보존 | 지원 |
| 누락된 하위 등급 | 실버부터 존재하면 브론즈를 생성하지 않음. 명시적 0 보존 | 지원 |
| 원시 파일 루트 | 이름을 키로 둔 객체와 원시 레코드는 거부 | 원시 어댑터 없음 |
| 원본 ID | `source_id`만으로 처리 불가. `id`와 다르더라도 관계를 검사하지 않음 | 원본 ID 선택·충돌 검증 필요 |
| 영웅·크기 매핑 | `Common`, `Hero8`, 문자열 `Small/Medium/Large`를 직접 처리하지 않음 | 검증된 매핑 필요. Hero8을 임의 영웅으로 해석하면 안 됨 |
| 등급별 누락값 상속 | 부분 전처리해 넣은 실버 수치에 브론즈의 누락 속성이 자동 상속되지 않음 | 미지원 |
| 설명 자리표시자 | 원시 `description`은 읽지 않음. 정규화 effects에 넣은 `{ability.0}`도 그대로 통과 | 미지원·미해석 표시 또는 거부 필요 |
| 능력·지속 효과 참조 | `raw_effects`의 참조를 해석·보존하지 않음 | 원시 참조 해석 필요 |
| 활성·디버그·템플릿·스킬 구분 | 부분 전처리해 정규화 레코드에 실어도 추가 메타데이터를 무시하고 통과 | 어댑터의 별도 제외·격리 단계 필요 |
| 전설 등급 | 현재 지원하는 네 등급 외 값은 명시적 거부 | 정책·UI 확장 전에는 자동 변환 불가 |
| 안전성 | 원시 형식 거부 시 기존 카탈로그 유지. 권한 미확인 시 요청 횟수 0 | 유지 |

## 특히 확인한 세 항목

**누락값 상속:** 합성 브론즈에는 피해 23·쿨다운 7500·충전량 1250, 실버에는 피해 61만 주었습니다. 합성 계약상 기대한 실버의 쿨다운·충전량이 현재 출력에는 없었습니다. 골드의 명시적 피해 0은 유지되었습니다. 이 검증은 실제 게임의 전체 상속 규칙을 증명하지 않습니다. 배열 참조의 상속·교체·삭제 및 null/빈 값 의미는 별도 원문 정의가 필요합니다.

**자리표시자:** 가상의 능력 0/1을 참조하는 설명을 넣었습니다. 현재 출력에는 자리표시자가 그대로 남습니다. 능력 번호가 어떤 속성·대상·단위를 의미하는지 현재 코드가 해석하지 않기 때문에 수치를 임의 대입하면 안 됩니다. 시간 단위 변환도 해당 액션 정의를 확인한 뒤 적용해야 합니다.

**비활성 구분:** 디버그/템플릿 모양의 합성 이름, 스킬 타입과 가상의 `active:false`를 시험했습니다. 부분 정규화 후에는 모두 통과합니다. `active:false`는 진단용 가상 필드이며 조사한 원본에 신뢰 가능한 활성 플래그가 있다는 뜻이 아닙니다. 이름에 `Test`가 있다는 이유만으로 일반 아이템을 제외해서도 안 됩니다. 원본의 활성 여부가 불명확하면 확인 대기 상태로 분리해야 합니다.

## 실행과 회귀 확인

```sh
npm run test:raw-contract
npm run test:data
npm run build
```

- 새 계약 진단 12건 통과. 미지원 확인 테스트도 포함.
- 기존 파이프라인 회귀 9건 통과.
- TypeScript 및 Vite 빌드 통과.
- 테스트 내부에서 UI 소스·스타일·생산용 카탈로그·권한 매니페스트가 변경되지 않았음을 바이트 비교.
- 모든 파일 출력은 임시 디렉터리이며 테스트 후 제거. 네트워크는 실제 호출하지 않음.
- 이번 변경은 테스트·실행 명령·이 문서뿐이므로 브라우저 UI 회귀 테스트는 다시 실행하지 않았습니다.

## 추가로 필요한 작업

1. 허가된 원시 공급원에 대한 독립 어댑터. `source_id`/`id` 관계와 중복·리네임 정책 확정.
2. 영웅·공용·크기 열거 매핑, 불명확한 코드의 격리 및 보고.
3. 실제 원문 계약에 맞는 등급 속성 상속, 능력·지속 효과 참조와 배열의 처리 규칙 검증.
4. 액션 타입별 설명 렌더링, 자리표시자 및 단위 변환. 미해석 토큰을 완성된 효과로 게시하지 않는 검증.
5. 공식 활성 풀 또는 검증된 상태 근거에 따른 비활성·디버그·템플릿·스킬 제외. 단순 이름 검사만으로 확정하지 않음.
6. 전설 등급의 지원 범위와 별도 이미지 공급원/사용 권한 확인.

실제 데이터 카탈로그는 여전히 0개입니다. 기존 샘플 및 저장 덱의 동작을 재작성하지 않았습니다.
